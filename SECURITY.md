# Security Policy

**Language:** **English** | [Tiếng Việt](docs/vi/SECURITY.md)

## Security Scope & Inherent Risks

**DeX 120Hz S22** is an experimental tool strictly scoped to a rooted **Samsung Galaxy S22 Exynos (`SM-S901B`, Android 12 / One UI 4.1)**. By architectural design, this project:

1. Executes privileged root shell commands via `su` inside `MainActivity` (`RootShell.exec`) to read `/sys/class/dp_sec/dex`, write `Settings.Global` (`dex120_*`), modify `Settings.System` / `Settings.Secure` (`refresh_rate_mode`, `min_refresh_rate`, `peak_refresh_rate`), invoke `service call SurfaceFlinger 1122 i32 60`, and collect `dumpsys` / `logcat` / `dmesg`.
2. Injects Java hooks via LSPosed into two privileged system processes:
   - `android` (`system_server`, UID `1000`)
   - `com.sec.android.sdhms` (Samsung Device Health Manager Service, UID `1000`)

Because of `system` (`UID 1000`) and `root` execution privileges, any defect in hook or shell logic directly impacts device stability and security. Inspect the source code carefully before installing.

## APK Signing Policy

Current `Pre-release` APKs are signed with a local/CI ephemeral debug keystore (`debug.keystore` auto-generated by `build.ps1` / `build.sh`, excluded by `.gitignore`, and **never** committed to Git). Because builds are experimental, always verify the accompanying `SHA-256` checksum or compile directly from source.

## Data NEVER Allowed in Repository, Issues, or PRs

Users and contributors must NEVER commit or paste publicly:

- Private keystores or APK signing keys (`.keystore`, `.jks`, `.pk8`, `.pem`) or keystore passwords.
- API keys or GitHub Personal Access Tokens (`ghp_...`, `gho_...`, `github_pat_...`).
- Hardware or personal device identifiers: **IMEI**, **Serial Numbers** (`ro.serialno`, `ro.boot.serialno`), Wi-Fi/Bluetooth **MAC** addresses, private LAN/ADB **IP** addresses.
- Raw `settings_*.xml` backups, `efs` partitions, or **Play Integrity** / hardware attestation tokens and certificates.
- Unsanitized `logcat`, `dumpsys`, or `dmesg` logs.

## Automatic Diagnostic Log Redaction

Before displaying or copying logs via **Copy Log**, `RootShell.sanitizeDiagnostics(String raw)` redacts sensitive patterns:

- GitHub tokens (`ghp_...`, `gho_...`, `github_pat_...`) → `[REDACTED_TOKEN]`
- Sensitive key-value pairs (`token`, `password`, `passwd`, `secret`, `api_key`, `authorization`, `bearer`) → preserves key name and masks value as `[REDACTED_SECRET]` (explicitly preserving harmless technical keys such as `dex120_block_token` and `token:[DMS]HardwareManager` / `SiopLimiterHrr`)
- `ro.serialno` / `ro.boot.serialno` / 11-character Samsung serials → `[REDACTED_SERIAL]`
- IMEI → `[REDACTED_IMEI]`
- MAC addresses → `[REDACTED_MAC]`
- Private/loopback IPv4 addresses (`10.x.x.x`, `172.16-31.x.x`, `192.168.x.x`, `127.x.x.x`) → `[REDACTED_IP]`
- Email addresses → `[REDACTED_EMAIL]`

> [!IMPORTANT]
> Automated regex redaction is a defense-in-depth helper only. **Always review copied logs line-by-line before posting them on GitHub Issues**, as third-party app logs or `dmesg` lines may contain custom Wi-Fi SSIDs or non-standard identifiers.

## Reporting a Vulnerability

Because this project is a device-specific experimental module with zero remote telemetry or backend servers:

- If you discover a vulnerability in the public repository, Java `RootShell`/hook code, or build scripts (`build.ps1` / `build.sh`, e.g., leaked secrets or command injection):
  - Contact the repository owner (`hangothanhh`) privately via GitHub Security Advisory (if enabled) or open an Issue **without full exploit payloads or private device data**.
  - Never attach third-party private keys or unredacted device logs when reporting security issues.
